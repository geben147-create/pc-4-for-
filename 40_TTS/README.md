# TTS + 장면 동기화

## 왜 방식 ③인가 — 세 가지 비교

| | 방식 | 문제 |
|---|---|---|
| ① | 문장 끝마다 전환 | 호흡은 자연스럽지만 **반전이 죽는다.** "공짜 점심은 없습니다" 의 충격이 문장 끝까지 기다리다 흩어진다 |
| ② | 핵심 단어마다 전환 | 강조는 살지만 **숨이 가쁘다.** 단어마다 화면이 바뀌면 시청자가 내용을 못 따라온다 |
| ③ | **의미 장면 고정 + 문장 끝/핵심 단어 병용** | 둘 다 해결. 채택 |

### ③의 구조

```
의미 장면 (SC01~SC24)   대본 논리 단위. 절대 쪼개지지 않는다
      └ 샷 전환          장면 안에서 문장 끝마다 (호흡 유지)
      └ 리빌 컷          반전 단어는 문장 끝을 기다리지 않고 그 단어에서 바로 (13곳)
```

---

## 핵심 — 컷 오프셋을 비대칭으로 둔다

여기가 이 설계의 전부다. **문장 끝 컷과 리빌 컷은 방향이 반대다.**

| 컷 종류 | 오프셋 | 이유 |
|---|---|---|
| 문장 끝 | **+120ms** (늦게) | 문장 끝에 정확히 붙이면 급하게 느껴진다. 숨 쉬는 지점에 컷이 걸려야 자연스럽다 |
| 리빌 단어 | **−80ms** (먼저) | **그림이 먼저 있고 말이 따라와야 '공개'가 된다** |

리빌에서 말이 먼저 나오고 그림이 늦으면 그건 공개가 아니라 **설명**이다.
시청자는 이미 들은 것을 그림으로 확인할 뿐이고, 놀라지 않는다.

80ms 먼저 그림을 띄우면 순서가 뒤집힌다. 화면이 먼저 바뀌고 → 시청자가 "뭐지?" 하는 순간 → 내레이션이 답을 준다.
이 0.08초가 반전을 만든다.

### 리빌 13곳

```
S006 훨씬 천천히      S029 공짜 점심        S032 수익의 일부
S045 제한될 수        S046 같은 숫자가 아닙니다  S053 총수익률
S064 무엇을 포기하고   S068 엔진 위에 얹는 장치   S069 순서가 뒤집힌
S079 약속된 월급이 아닙니다  S082 원금이 감소할
S094 이 차이가        S098 내 목적에 맞는
```

가장 중요한 것은 **S068 "엔진 위에 얹는 장치"** 다.
이 단어가 발음되기 80ms 전에 18번 컷(엔진 위 검은 모듈)이 떠 있어야 한다.

## 왜 문장별로 따로 생성하는가

Qwen3 VoiceBox 는 Edge TTS 와 달리 **단어 단위 타임스탬프를 주지 않는다.**
마스터 WAV 한 개를 만들면 장면 타이밍을 귀로 찾아야 한다.

문장별로 생성하면 타이밍이 **추정이 아니라 계산**이 된다.

| | 마스터 1개 | 문장별 98개 |
|---|---|---|
| 장면 타이밍 | 귀로 찾음 | 길이 합산으로 계산 |
| 한 문장 수정 | 전체 재생성 | 그 문장만 |
| **일본어판** | 처음부터 다시 | **같은 문장 ID로 교체, 장면 ID 유지** |

---

## 일본어판 설계

장면 ID 는 **언어와 무관하다.** 바뀌는 것은 음성 길이뿐이다.

```
sentences_ko.tsv   S001..S098  scene_id SC01..SC24   ← 한국어
sentences_ja.tsv   S001..S098  scene_id SC01..SC24   ← 같은 ID, 일본어 문장
```

1. `sentences_ko.tsv` 를 복사해 `text_spoken` 만 일본어로 교체한다
2. `scene_id`, `sent_id`, `cut_type` 은 **절대 건드리지 않는다**
3. `reveal_word` 만 일본어 대응어로 바꾼다
4. `01_audio/ja/S001.wav ...` 로 생성
5. `python build_timeline.py --lang ja`

이미지 24컷과 영상은 **그대로 재사용**된다. 타이밍만 다시 계산된다.

> 일본어는 한국어보다 같은 내용에서 음절이 길어지는 경향이 있다. 총 길이가 늘어나면
> `MAX_SHOT_S` 초과 샷이 많아지므로, 그 샷들은 카메라 무브를 더 넣거나 클립을 2개로 나눈다.

## 실행

### 1. 음성 생성 (로컬 Qwen3)

`VOICE_PROFILE.md` 의 V2 프로필로 `sentences_ko.tsv` 의 98문장을 각각 생성한다.

```
01_audio/ko/S001.wav ... S098.wav     (24000Hz Mono, -16 LUFS)
```

**파일명이 `S001.wav` 형식이 아니면 동작하지 않는다.**

### 2. 타임라인 산출

```bash
python build_timeline.py --lang ko            # 타임라인 + 자막 + 편집 CSV
python build_timeline.py --lang ko --concat   # 마스터 WAV 도 생성
```

표준 라이브러리만 쓴다. pip 설치 불필요.

### 3. 출력

```
out/timeline_ko.json    샷별 start/end/scene_id/리빌 여부
out/subtitles_ko.srt    문장 단위 자막
out/edit_ko.csv         편집 프로그램 임포트용
out/master_ko.wav       --concat 지정 시
```

초당 7.8자 기준 — 실제 값은 진짜 음성에서 확정된다.

| 항목 | 값 |
|---|---|
| 총 길이 | 8분 40초 (목표 8:30에 근접) |
| 문장 | 98개 |
| 샷 | **86개** |
| 평균 샷 길이 | 5.3초 (무료 영상 클립 5초와 일치) |
| 리빌 컷 | 13개 |
| 6초 초과 샷 | 26개 → 클립 2개로 분할 또는 카메라 무브 |

총 클립 수 ≈ 86 + 26 = **약 112개**.

> 속도가 다르면 총 길이가 달라진다. 실제 음성 생성 후 `build_timeline.py` 가 정확한 값을 낸다.
> 8:30 을 맞춰야 하면 Qwen3 속도(현재 1.10배)를 조정한다.

## 파라미터 조정

`build_timeline.py` 상단에서 바꾼다.

```python
GAP_MS                 = 180   # 문장 사이 간격
CUT_OFFSET_SENTENCE_MS = 120   # 문장 끝 컷을 늦추는 양
CUT_OFFSET_REVEAL_MS   = -80   # 리빌 컷을 당기는 양
MIN_SHOT_S             = 2.2   # 이보다 짧으면 앞 샷에 흡수
MAX_SHOT_S             = 6.0   # 초과 시 경고 (클립 분할 필요)
```

컷이 급하게 느껴지면 `CUT_OFFSET_SENTENCE_MS` 를 150~200 으로 올린다.
반전이 약하면 `CUT_OFFSET_REVEAL_MS` 를 −120 까지 당긴다. 그 이상은 그림이 먼저 튀어 보인다.

### 병합 규칙 주의

짧은 샷은 앞 샷에 흡수되지만, **흡수 결과가 `MAX_SHOT_S` 를 넘기면 흡수하지 않는다.**
이 제한이 없으면 짧은 문장이 몰린 오프닝 훅이 통째로 한 장의 정지 화면이 된다.
실제 검증에서 이 규칙 없이는 SH001 이 12.7초짜리 정지 화면이었다. 훅에서 가장 치명적이다.
